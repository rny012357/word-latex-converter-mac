# 対象範囲と制限

## 原文保持の範囲

`OMaths.Add`、`BuildUp`、構造検査の失敗は作業用文書の中で起きるため、その段階では本文を変更しません。
貼り戻しには [`Range.FormattedText`](https://learn.microsoft.com/en-us/office/vba/api/word.range.formattedtext) を使い、その直前に対象の書式付きテキストを別の作業用文書へ退避します。
貼り戻し中または直後の検査でエラーが出た場合は、本文全体の長さの差から置換後の範囲を求め、退避内容で復元します。

**貼り戻し直後に意図的に失敗させる実機テストで、元の文字列と本文長の復元を確認しました。**
すべての書式属性や文書メタデータの完全な復元は未検証です。
WordやOSの終了、強制停止、メモリ不足、同時編集、マクロのリセットでは復元処理自体が実行されない場合があります。
復元に失敗した場合は、その時点で中断し、エラーメッセージに `ROLLBACK FAILED; STOPPED` を表示します。
既存の文書操作を誤って取り消さないよう、復元に `Undo` は使いません。
ファイルの自動保存やバックアップ作成は行わないため、文書のコピーを用いてください。

## 検出の規則

| 入力 | 扱い |
| --- | --- |
| `\(...\)`、`$...$` | インライン数式。段落、改行、セル境界を越えない |
| `\[...\]`、`$$...$$` | 表示用の区切り。単一の段落区切りや手動改行を含められる |
| 表示数式中の連続した段落区切り | 未閉鎖式が通常の文章を巻き込まないよう探索を打ち切る |
| 区切りと異なる区切りが途中に現れる | その候補を打ち切り、次の区切りから再開する |
| `\$` | 区切りとして使わない。バックスラッシュも本文に残す |
| ドル記号の直前にある連続バックスラッシュ | 奇数ならエスケープ、偶数なら区切りになり得る |
| `$$$` 以上の連続 | 区切りとして使わない。候補の中なら探索を打ち切る |
| `$ x$`、`$x $` | 単一ドルの直後や直前に空白があるため変換しない |
| 空の `\(\)` | 候補にはなるが組版前に拒否し、原文を残す |
| 本体が16,000文字を超える式 | 探索を打ち切る |

表示数式の改行は、作業用文書へ渡す前に空白へ変換します。
成功時には区切りの内側にあった段落も数式に置き換わるため、元の段落配置を維持する用途には向きません。
段落のスタイルや番号が異なる範囲をまたぐ式は、先に同じ段落へ整理してください。
`\\` というLaTeXの行区切りは文字として維持します。

LaTeXの完全な構文解析器ではありません。
コメント、verbatim、コードブロック、URL、独自マクロ、`\text{...}` 内のドル記号などは特別扱いしません。
コードの説明文中にある `$x$` も数式として検出し得るため、そのような文章では選択範囲を使ってください。
未閉鎖式の内側にある別の区切りは、新しい候補になる場合があります。

`$100$` のような金額と数式の曖昧性は判定できません。
通常のドル記号を `\$` と書くか、モジュール冒頭の `ENABLE_DOLLARS` を `False` にして `\(...\)` と `\[...\]` のみを使ってください。

## 編集から保護するもの

既存のWord数式、フィールド、コンテンツコントロールは検出の前に覆い、候補がそれらをまたがないようにします。
さらに、候補と重なる既存数式、フィールド、コンテンツコントロール、ブックマーク、コメントの対象範囲、候補内のハイパーリンクとインライン図形は貼り戻しの前に除外します。
本文以外のストーリー、矩形選択、編集保護された文書、変更履歴を記録中または履歴が残る文書は対象外です。
表ではセル末尾記号を越える候補を作りません。

これらはWordのオブジェクトモデルで取得できた範囲に対する保護です。
浮動図形のアンカー、すべての文書メタデータ、共同編集による同時変更までは復元対象に含みません。
Wordの文字位置と取得テキストの位置が一致しない場合は、実際の範囲テキストとの照合で候補を除外します。
絵文字、特殊文字、フィールド、非表示文字の近くでは変換対象が残る場合があるため、実機で確認してください。

## 組版判定の限界

入力形式を切り替える操作は行いません。
実行前にWordの数式入力形式をLaTeXに設定し、新しい作業用文書でもその設定が使われるかを基本テストで確認してください。
Wordのビルドによって、UIでのLaTeX入力と `BuildUp` の処理経路が同じとは限りません。

`BuildUp` の正常終了に加え、未変換の英字コマンドの残存、波括弧の釣り合い、`bmatrix` の開始と終了の個数、生成された行列数、`\frac` の分数要素数を確認します。
XMLの検査には [`Range.WordOpenXML`](https://learn.microsoft.com/en-us/office/vba/api/word.range.wordopenxml) を使い、Wordの通常の `m:` 接頭辞を前提にしています。
別の接頭辞や取得エラーが生じた場合は、成功とせず原文を残します。

検査を通過しても、行列の寸法、セル順、括弧、総和の上下限、微分記号の位置、文字の欠落などは目視確認が必要です。
別種の行列が混在する式では、`bmatrix` の個数と生成行列の総数が一致せず、正しい式でも保守的に未変換とする場合があります。
意図してバックスラッシュ付きの英字を表示する数式も、未変換コマンドとして拒否する場合があります。

`Converted` は実装内の検査を通過した件数です。
`Retained` は変換や貼り戻しに失敗して原文を残した候補数、`Protected candidates` は位置照合や保護判定で除外した候補数、`Delimiter issues` は閉じられずに探索を打ち切った開始候補数です。
あらかじめ覆った既存数式は候補にならないため、`Protected candidates` に既存数式の総数は表示されません。

## 実機で残った制限

Word 16.114（ビルド16.114.1020）、LaTeX入力形式で、今回の2個から3個の `bmatrix` を含む代表式は `BuildUp` で失敗しました。
この失敗を元のLaTeXのまま残す動作は確認しましたが、複数行列の変換成功は保証しません。

基本テストの4式は、保存したWord文書でインラインのOMathになっていました。
`\[...\]` と `$$...$$` も認識しますが、文章から切り離した表示数式の段落は自動で作りません。
表示数式が必要な場合は、Word側で段落と表示形式を調整してください。
