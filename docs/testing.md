# 導入と実機テスト

## 検証の前提

**Mac版Word 16.114（ビルド16.114.1020）で、コンパイル、基本テスト、自己テスト、行列診断、実際の失敗式の原文保持を実施しました。**
検証結果は [実機検証記録](validation.md) に記録しています。
表中の追加テストすべてを実施したわけではありません。
原本をコピーし、そのコピーで試してください。
既存の `ConvertLaTexInDocument` と新しいモジュールを同時に有効にすると、名前が衝突したり旧版を実行したりする場合があります。
旧モジュールは先にエクスポートして保管し、検証用文書には新しいモジュールだけを置いてください。

## モジュールの読み込み

1. Mac版Wordで新しい空白文書を作り、検証用の名前で `.docm`（Wordマクロ有効文書）として保存します。
2. ［ツール］→［マクロ］→［Visual Basic Editor］、または［開発］→［Visual Basic］を開きます。
3. プロジェクト一覧で、その検証用文書を選びます。初回は `Normal` へ導入せず、文書内で試します。
4. ［ファイル］→［ファイルのインポート］から `WordLaTexConverter.bas` を読み込みます。
5. ［デバッグ］→［プロジェクトのコンパイル］を実行します。エラーが出たら、行とメッセージを記録して以後の変換を止めます。
6. Wordへ戻り、数式を1つ挿入して、［数式］タブの入力形式がLaTeXになっていることを確認します。メニューの名称や配置はビルドにより異なります。
7. テスト用文書のマクロを実行します。参照設定の追加、VBAプロジェクトへのプログラムアクセスの許可、外部スクリプトは必要ありません。

コード画面へ貼り付ける場合は、`WordLaTexConverter-paste.txt` を標準モジュールへ貼り付けます。
`.bas` の先頭の `Attribute VB_Name = ...` 行をコード画面に貼り付けると構文エラーになります。
通常はインポートを使用してください。
マクロの許可は組織の設定に従い、この検証用文書に必要な範囲で行います。

## 基本テスト

［ツール］→［マクロ］→［マクロ］で `CreateLaTexSmokeTest` を実行します。
新しい文書に4式とエスケープされた金額を、クリップボードを使わずに書き込みます。
これは、新しいWordで貼り付け時に自動で数式になる動作と、マクロの動作を分けるためです。

生成された文書で文字を選択せず、本文内にカーソルを置いて `ConvertLaTexInDocument` を実行します。
結果の目標は `Converted: 4`、`Retained: 0`、`Protected candidates: 0`、`Delimiter issues: 0` です。
本体を確認し、4式がWordの数式になり、`\$100` の文字列がそのまま残ることを確認します。
分数の横線、総和の上下限、上付きと下付き、上線も目視で確認します。

ルートにある `smoke-test.txt` を使う場合は、文字列として貼り付けます。
実行前にLaTeXの区切りが文字として残り、Word数式へ自動変換されていないことを確認してください。

同じ文書でもう一度変換します。
2回目の目標は `Converted: 0`、`Retained: 0` です。
1回目の数式数と本文が変わらないことを確認します。

## 自己テスト

`SelfTestLaTexConverter` を実行すると、テスト専用の文書を内部で作り、最後に結果文書を表示します。
結果の目標は `Passed=24 Failed=0` です。
自己テストは利用者の本文を入力として使いません。
予期しないエラーで停止した場合、テスト途中の文書が残る場合があります。

| 判定 | 数 | 受入条件 |
| --- | ---: | --- |
| 区切り、エスケープ、改行、再開位置 | 16 | 4形式、隣接式、奇数と偶数のエスケープ、3連続ドル、未閉鎖、既存数式境界を判定できる |
| Unicodeバックスラッシュと波括弧 | 3 | 実際のU+005Cの区切りを認識し、正常、未閉鎖、エスケープされた括弧を区別できる |
| `BuildUp` の失敗 | 1 | 中央の式だけ原文保持し、左右の式は変換する |
| 貼り戻し直後の失敗 | 1 | 置換済みの式を元の区切り付き文字列へ戻し、左右の式は変換する |
| 再実行 | 1 | 復元対象は保持され、既存数式が増殖しない |
| 選択範囲 | 1 | 本文の途中の式だけを変換し、外側の2式を残す |
| 既存数式内のドル | 1 | 既存数式内の `$hidden$` を検出し直さず、外側の2式だけを変換する |

意図的な失敗は、内部呼び出しのテスト引数を指定したときだけ有効になります。
通常の一括変換は、その引数を指定しません。
実際のWordが異なる理由で先に失敗した場合は、結果の件数だけで合格とせず、VBAの［表示］→［イミディエイト ウィンドウ］で `Injected BuildUp failure` と `Injected failure after replacement` の両方が記録されたことを確認します。

復元の見た目は追加で確認します。
原文の一部を太字や色付きにした候補について、デバッガーで `CommitEquation` の貼り戻し直後にエラーを発生させるか、テスト用の `\(FAIL_COMMIT\)` を同じテスト経路で処理し、文字の書式が復元されるかを確認してください。
現在の自己テストが自動で照合するのは原文テキストと本文長であり、すべての書式属性の一致ではありません。

## 保護と境界の追加テスト

次の項目は自己テストに含まれないため、実機で個別に確認します。

| ケース | 手順 | 期待する結果 |
| --- | --- | --- |
| ギリシャ文字 | `\(\alpha+\beta=\gamma\)` を変換 | 3文字が数式文字になる |
| 不正な式 | `\(a\) \(\frac{1}{2\) \(b\)` を変換 | 中央を保持し、左右を変換 |
| 未知のコマンド | `\(a\) \(\DefinitelyUnknownCommand{x}\) \(b\)` を変換 | 未変換コマンドが残るなら中央を保持 |
| フィールド | フィールド結果をまたぐ開始と終了記号を配置 | フィールドを含む候補を変換しない |
| コンテンツコントロール | 内部または境界をまたいで区切りを配置 | 対象を変換しない |
| ブックマーク、コメント、ハイパーリンク | 対象式にそれぞれ設定 | 対象候補を除外し、他の式を変換 |
| 変更履歴 | 記録をオン、または変更履歴を残して実行 | 本文を変更せず終了 |
| セル境界 | 開始と終了を別々のセルに置く | セルをまたいだ変換を行わない |
| 絵文字と非表示文字 | それらの後ろに通常の式を置く | 正しい位置だけを変換する。不一致なら原文保持 |
| 複数行の表示式 | `\[` と `\]` の間に単一の段落区切りを置く | 1式として変換。内部の段落は数式に置き換わる |
| 空白段落 | 表示式の途中に連続する段落区切りを置く | そこで探索を打ち切る |
| 選択範囲の切断 | 開始または終了だけを含む選択範囲で実行 | 選択範囲外を変更しない |

## 行列の診断

`DiagnoseLaTexMatrices` は7ケースを試し、入力文字列、エラー段階、エラー番号、行列数、成功時の数式を新しい結果文書に並べます。
構造判定の `PASS` に加え、角括弧、行列の寸法、各セル、微分記号を確認してください。
1つの式に含まれる行列が、1つのWord数式の中にあることも確認します。

LaTeX入力形式で診断した後、比較用にUnicodeMath入力形式でも実行し、どちらの結果文書にも入力形式を手で追記します。
診断マクロは入力形式を自動で取得または変更しません。
終わったら通常使用する入力形式へ戻します。
結果の読み方は [行列の調査記録](matrix-investigation.md)を参照してください。


対象文書で必要な保護テストを通過するまで、本番の原本に適用しないでください。
行列3個の修正判定には、以前失敗した正確な文字列でも再テストし、原文を残した安全な失敗と変換成功を区別する必要があります。

今回の基本テストは、表示用の区切りも文章と同じ段落に配置しています。
保存後の4式はいずれもインラインのOMathであり、表示数式の段落構造を自動で作る動作は確認できていません。
別行の表示数式が必要な場合は、Word側で段落と表示形式を確認してください。
