# Mac版Wordでの検証記録

2026年11月5日に、次の環境で実施しました。

| 項目 | 値 |
| --- | --- |
| macOS | 27.0.1 |
| WordのVBAが返したバージョン | 16.114 |
| Wordのビルド | 16.114.1020 |
| アプリのバンドル情報 | 16.114.1 |
| 数式入力形式 | LaTeX |

## 実施した検証

| 検証 | 結果 |
| --- | --- |
| VBAコンパイル | 成功 |
| `SelfTestLaTexConverter` | 24成功、0失敗 |
| 4形式の基本入力 | 変換4件、原文保持0件 |
| 基本入力を再実行 | 変換0件、原文保持0件 |
| 保存した基本入力のXML | Word数式4個、分数要素2個、総和要素1個 |
| 実際の3行列の失敗式を挟んだ入力 | 変換2件、原文保持1件 |
| 失敗式と金額の原文照合 | 保存したXMLで完全一致 |

基本入力と失敗式を挟んだ入力は、画面上でも確認しました。
表示用の区切りを含む基本入力の4式は、保存後はいずれもインラインのOMathでした。
独立した表示数式の段落を作る動作は確認できていません。

## 自己テストの範囲

- 4種類の区切り、隣接式、エスケープの偶奇、3連続ドル、未閉鎖式、改行、保護境界。
- 実際のU+005Cのバックスラッシュと、波括弧の釣り合い。
- 意図的な `BuildUp` の失敗後の原文保持と、前後の式の変換。
- 貼り戻し直後に意図的に失敗させた場合の、元の文字列と本文長の復元。
- 再実行、選択範囲外の保持、ドル記号を含む既存数式の保護。

すべての書式属性や文書メタデータの復元を自動で照合するテストではありません。

## 実機で修正した点

同じ作業用文書へ数式を繰り返し上書きすると、後続の単純な式でも `BuildUp` が失敗しました。
式ごとに新しい文書を作って閉じる方式へ変更し、失敗後も前後の通常式を変換できることを確認しました。
この変更で複数行列の問題は解消していません。

コード内のバックスラッシュは `ChrW(92)` で生成します。
VBAエディターの日本語環境での文字の違いを避けるための処理です。
インポート用の属性行を含まない貼り付け専用の `.txt` も用意しています。

## 行列診断

| ケース | 入力 | 結果 |
| --- | --- | --- |
| 1 | 行列1個 | 成功、行列要素1個 |
| 2 | 行列2個 | `BuildUp` 失敗、エラー -2147467259 |
| 3 | 行列3個 | 同じエラー |
| 4 | 微分入り3行列 | 同じエラー |
| 5 | 1×1行列3個 | 同じエラー |
| 6 | 旧来のLaTeX風構文 | 行列数0で構造検査に不合格 |
| 7 | UnicodeMath構文 | LaTeXモードでは行列数0。UnicodeMathモードでの比較は未実施 |

開発時の既存マクロでは2行列の成功報告もあり、今回の環境と結果が異なります。
文字列、ビルド、設定の差を分離できていないため、個数をWordの仕様上の上限とは判定しません。
詳しくは [行列の調査](matrix-investigation.md) に記録しています。
